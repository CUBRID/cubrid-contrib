# 아키텍처 (Architecture)

## 1. 설계 원칙 — 쓰기·락 0, 읽기 최소

volmap은 서버에 접속하지 않고 볼륨 파일을 읽기 전용으로 연다. 쓰기와 락은 없지만 읽기 I/O는 있다 — README의 [실행 중 DB에서 쓸 때](../README.md#실행-중-db에서-쓸-때) 참고.

| 원칙 | 구현 |
|---|---|
| 서버 무접촉 | 볼륨 바이너리 파일을 `O_RDONLY`로 직접 해석. 서버 프로세스·페이지 버퍼·락 테이블에 일절 접근하지 않음 |
| 락 0 | 파일 락(`flock`/`fcntl`) 미사용. DB 락은 접속 자체가 없어 원천 불가 — 전수 스캔 중 `cubrid lockdb` 기준 잡힌 객체 0 |
| 쓰기 0 | 볼륨 fd는 커널 수준에서 읽기 전용 — 결함이 있어도 파일 훼손이 불가능한 구조 |
| 읽기 최소 | 기본 실행은 볼륨 헤더·섹터 테이블·파일 트래커·파일마다 헤더 1페이지와 그 파일 테이블만 읽는다. 예약 공간이 아니라 파일 수에 비례: 콜드 97GB 에서 31MB — README [실행 중 DB에서 쓸 때](../README.md#실행-중-db에서-쓸-때) |
| 오프셋 하드코딩 0 | 페이지·볼륨 구조체는 엔진 헤더를 `#include` — 오프셋은 컴파일러가 계산한다. 파일 디스크립터 구조체는 사본(`storage_ondisk_layout.hpp`)이라 포맷 변경이 컴파일로 드러나지 않는다 |
| 자기검증 3중 | 볼륨 magic / FILE_HEADER self VFID / 페이지 prv.pageid — 불일치 항목은 폐기 (틀린 지도를 그리지 않음) |

기동 중 DB에도, 정지된 DB에도 같은 방식으로 읽는다 (CS/SA 모드 구분 자체가 없음). 실행 중인지는
판정하지 않고, 액티브 로그 헤더의 `is_shutdown` 으로 마지막 종료가 정상이었는지만 표시한다.
기동 중에는 더티 페이지 미반영분이 존재할 수 있다. 그 차이를 보려면 `cub_top --bcb-dump`
스냅샷을 `--bufmap` 으로 겹쳐 본다 — 페이지 단위 상주·더티와 LSA 비교까지 나온다.

## 2. 데이터 흐름

```
볼륨 바이너리 직접 해석 (서버 호출 0)
  *_vinf ──▶ DISK_VOLUME_HEADER 파싱 (magic 검증)
         ──▶ 같은 디렉터리의 <db>_t<N> 임시 볼륨 자동 탐지 (vinf 미등재 파일)
  L1: 섹터 할당 테이블(1비트/섹터) 읽기
  파일 자기발견: 예약 섹터 첫 페이지의 prv(ptype==FTAB) 프로브
                 → FILE_HEADER 파싱 → self VFID == 자기 VPID 일치 시 파일 확정
                 (file_create의 할당 순서상 파일 헤더는 섹터 첫 페이지에 위치)
  FILE_DESCRIPTORS: 힙 → class OID, 인덱스 → BTID의 class OID
  L2/L3: partial/full 섹터 테이블(extdata 체인, 볼륨 경계 통과) → 페이지 비트맵·실사용 수
  L4(--deep): SPAGE_HEADER(각 페이지 선두에 영속) → 레코드 밀도·포워딩 비율
  TDE 감지: prv.pflag의 암호화 비트(AES/ARIA) — 감지 시 'E' 표기 + note 보고(finding 아님). 트래커로 찾은 파일의 섹터는
  프로브하지 않으므로 볼륨당 64 섹터를 고르게 골라 첫 페이지 32B 만 표본한다
  OID→클래스명: 클래스 레코드의 첫 가변속성 = 이름 (or_class_name과 동일 원리,
                REC_RELOCATION→REC_NEWHOME 추적, REC_BIGONE→오버플로 first-part 파싱)
  인덱스명: 클래스 레코드 property list의 BTID 문자열("vol|file|root") 역방향 탐색
  -m: mmap+mincore → OS 페이지캐시 상주율 (커널 메타데이터만 — 읽기·폴트·락 0)
  -B: cub_top --bcb-dump 스냅샷(CBCBMAP1) → 볼륨별 페이지 배열(0/clean/unflushed = DIRTY 또는 FLUSHING) + 접두합 → 셀 배경 층,
      (volid,pageid) 정렬 배열 → 페이지 박스에서 메모리 LSA vs 디스크 prv.lsa 비교

```

핵심 아이디어는 **파일 자기발견(self-discovery)** 이다. 서버·카탈로그·csql에 묻지 않고
볼륨 바이너리만으로 모든 파일(사용자 테이블·인덱스는 물론 파일 트래커, vacuum data,
dropped files 같은 내부 파일까지)을 찾아낸다. 카탈로그 조회보다 오히려 완전하다
(내부 파일은 카탈로그에 없다).

## 3. 렌더러 — 정보 인코딩

한 글리프에 4개 축(종류=색, 경계=톤 토글, 채움=점자 램프, 상태=전용 글리프)을 싣는다.
상세는 README의 "지도 읽는 법" 참고. **색 계약**: 같은 파일 = 어디서든 같은 색이며,
같은 종류색이 지도 셀 → 오버레이 섹터 그리드 → 페이지 바이트 뷰의 rec 셀 → 이름 배지
(` H `/` I ` — ASCII 한 글자 색 칩: 폰트·폭 무결) 배경까지 일관되게 흐른다. 해상도는 1칸 = ⌈볼륨 총페이지/칸수⌉ 페이지로 자동
결정되고 헤더에 `(cell = N pages = X)`로 표기된다.

**글리프 안전 규칙**: 6점 점자(U+2800–283F) + 블록 요소 일부 + ASCII만 사용한다.
Geometric Shapes(●◕◓◔■◆)·Box Drawing(│)·화살표(→)는 East-Asian **ambiguous width**라서
CJK 터미널에서 2칸으로 렌더되어 그리드가 어긋난다. 8점 점자(U+2840+)는 폰트 커버리지가
낮아 두부(tofu)가 된다. 색은 기본 ANSI(30/90번대)+그레이 위주로 8컬러 콘솔에서도 동일하게
보이며, `--plain`은 이스케이프 없는 순수 ASCII로 강등된다.

## 4. 인터랙티브 TUI 프레임 파이프라인

ncurses 없이 순수 ANSI(SGR 마우스 1006h + termios raw + autowrap OFF)로 구현되어 단독
바이너리에서도 동일하게 동작한다. 대체 화면(1049h)은 쓰지 않는다 — 종료 후에도 마지막
프레임이 터미널에 남아, 보고 있던 것을 복사·공유할 수 있다.

### 화면 영역과 갱신 정책 (부분 리페인트)

```
행 1        범례 (고정)
행 2        [n/N] 볼륨 헤더 (스캔 중 scanning NN%)
행 3        (공백)
행 4..H-4   라운드 프레임 지도 — 상단 inset: DB명·할당 통계 / 하단 inset: 볼륨 파일 경로
            (오버레이가 열리면 지도 위에 4박스 스택이 겹침 — 커서 반대편 배치)
행 H-3..H-2 인스펙션 2줄 (커서 대상 FULL 상세, live)
행 H-1      키 목록
```

| 이벤트 | 리페인트 범위 |
|---|---|
| 커서 이동(화살표/클릭) | **변경 2셀 + 하단 바**만 (맵 재계산·pread 0) |
| 오버레이 내 선택 이동 | 오버레이 박스들 + 하단 바 |
| 볼륨 전환·오버레이 열기/닫기·좌우 재배치·리사이즈·새로고침·상주 토글 | 전체(full) 프레임 |

full 프레임에서 각 맵 셀의 렌더 결과(SGR+글리프, 셀당 최대 32바이트)를 `cell_render[]`에
보존한다. 부분 프레임은 이 저장본으로 이전 커서 셀을 복원하고 새 커서 셀을 역상으로 그린다.
모든 셀 문자열은 `\033[0m`으로 시작하므로, 커서 역상은 그 리셋 **뒤에** 적용한다
(앞에 두면 리셋이 역상을 지운다).

### 글리프-완결 write 경계 (터미널 깨짐 방지)

write 경계가 멀티바이트 글리프 중간에 떨어지면 일부 터미널이 그 자리를 U+FFFD(�)로
렌더한다. 두 경로 모두 막는다:

1. tty stdout의 기본 flush(약 1KB)가 행 중간에서 프레임을 쪼개는 것 →
   `setvbuf(_IOFBF, 1MB)` 전체 버퍼링으로 차단.
2. 대형 프레임을 커널이 pty 4KB 청크로 다시 쪼개는 것(타이밍 의존) →
   **매 행 flush**(행당 write ≤1.6KB < 4KB — strace 전수 실측으로 분절 0) + 4행마다
   `tcdrain`. 패킷 경계에서 UTF-8을 재조립하지 못하는 일부 SSH 클라이언트까지 커버한다.

추가로 화살표는 SS3(`ESC O x`) 변형도 CSI로 정규화해 받고, 매 프레임 끝에 커서를
재숨김(?25l)+우하단 파킹한다 — 커서 숨김을 무시하는 클라이언트에서도 그리기 커서의
점프가 보이지 않는다.

여기에 **SGR 런 압축**(같은 SGR이 연속되면 글리프만 출력, 행 단위 리셋)으로 전체 프레임을
약 3분의 1로 줄이고(40KB→약 14KB, write당 ≤4KB), 프레임을 `ESC[?2026h/l`(synchronized
update)로 감싸 지원 터미널에서는 tearing까지 차단한다.

### 드릴다운 오버레이 (지도 위 4박스 스택)

커서 대상의 내부를 지도 위에 겹치는 세로 스택으로 보여준다 — [섹터 그리드 32×2] →
[페이지 바이트 분포] → [슬롯(스크롤 창)] → [info]. space/enter 한 키로 지도→섹터→페이지→
슬롯→지도 를 순환하고, 위 박스의 선택이 아래 박스들을 실시간 갱신한다. 화면별 상세는
[views.md](views.md) §3.

- 섹터의 페이지들은 **1MB 단일 pread** 로 읽는다 (64회 분산 프로브 대신 — 시크 1회).
- 페이지 바이트 분포는 flat 렌더 — 셀 = ⌈user영역/셀수⌉ 바이트(8배수)의 **다수결 클래스**,
  페이지 전 바이트가 셀 행 안에 표현된다. 커서는 데이터가 있는 셀에만 머문다.
- 색 계약: rec 셀 = 소유 파일의 종류색(지도와 동일), 공간 클래스(free/dir/frag)는 중립 회색 —
  바이트 뷰가 지도 종류색과 절대 충돌하지 않는다.
- 마우스 히트테스트는 오버레이의 **실제 사각형**(테두리 포함)만 캡처한다 — 박스 위/아래의
  지도는 오버레이가 떠 있어도 계속 클릭된다.
- 패널은 (level, key) 캐시를 가져 같은 대상을 다시 그릴 때 I/O 가 없다.

### 점진 기동 (progressive startup)

`-i` 는 전수 파일 자기발견을 기다리지 않는다: 섹터 테이블만 읽고
**즉시 첫 프레임을 그린 뒤**(섹터 테이블만 읽으므로 수십 ms 안쪽, 90GB 콜드), 자기발견은 **배치 워커 스레드**가
슬라이스(시간 상한 300ms, 최근 2초 안에 키 입력이 있었거나 디스크가 바쁘면 50ms)로 진행한다 — UI 는 스캔과 완전히 분리되어 콜드 디스크에서도
키 응답이 수십 ms 를 유지한다(§6).

볼륨 순서는 **양끝 교차**다: [보고 있는 볼륨] → 첫 볼륨 → 마지막 볼륨 → 둘째 → 뒤에서
둘째 → …. 최신 데이터가 몰리는 끝 볼륨이 두 번째로 완성되므로 `>` 로 끝에 바로 가도 곧
채워진다. 볼륨 내부는 순차 유지 — WILLNEED 리드어헤드의 연속 run 병합(콜드 9.8GB→1.4GB
최적화)이 순차 접근을 전제한다.

진행률은 헤더에 `scanning NN%` 로 표시되고, 아직 귀속되지 않은 예약 셀은 회색 `⠒`
자리표시로 그린다. 스캔 완료 시 실제 소유 색으로 바뀐다.

### 파일 탐색: 트래커 먼저, 프로브는 나머지만

엔진은 모든 파일을 **파일 트래커**에 등록한다(`file_tracker_register/unregister`). 그 목록을 읽는
경로는 엔진과 같다 — 볼륨 0 헤더의 `boot_hfid` → 부트 힙의 첫 레코드 `BOOT_DB_PARM`(첫 필드가
`trk_vfid`, 10.1~11.5 동일) → 트래커 파일의 sticky first page → `FILE_EXTENSIBLE_DATA` 체인
(`vpid_next`), 아이템은 16B `{fileid, volid, type, metadata}`. 각 단계는 그 자리에 있어야 할
것(힙 헤더, `FILE_TRACKER` 헤더, 16B 아이템)으로 자기검증하고, 실패하면 예전 방식으로 넘어간다.

| 단계 | 읽는 것 |
|---|---|
| 트래커 | 볼륨 0 헤더 1 + 부트 힙 2~3 + 트래커 페이지(파일 1,000개당 1) + **파일마다 헤더 1 페이지** + 섹터 테이블(ftab) 페이지 |
| 프로브 | 어느 파일도 소유하지 않는 예약 섹터의 첫 페이지 32B(OS 는 4KB). 삭제돼 vacuum 을 기다리는 파일과 만들어지는 중인 파일이 여기서 나온다 |
| 2차 탐색 | 그래도 소유자가 없는 섹터 ≤256 이면 전 페이지(`--full-sweep` 은 전부) |

실측(콜드, 97GB cbench, 파일 76개): 배치 31MB, `-i` 탐색 완료까지 31MB(소요는 디스크에 따라 다르다). 트래커를 끄면
(`--no-tracker`) 83MB — 프로브도 **이미 소유가 확정된 섹터는 건너뛰므로** 예전의 405MB 와 다르다.
트래커 자체도 파일이라 목록에 넣고(`TRACKER`), 자기 자신은 목록에 없으므로 그 하나만 따로 표시한다.
`refresh` 는 기존 파일의 ftab 재순회 뒤 트래커를 다시 읽어 새 파일을 찾고, 그 뒤 무소유 섹터만 프로브한다.

### 옆에서 도는 것: /proc 두 파일

서버에 묻지 않고 알 수 있는 공개 정보는 프로세스 명령줄(`/proc/<pid>/cmdline`)과 소켓 표
(`/proc/net/unix`)다. `cub_server <db>` 가 있고 그 pid 의 `cubrid_tcp_setup_server<pid>` 가
소켓 표에 있으면 실행 중, 없으면 기동·복구 중이다(`network_sr.c`: `css_init` 은
`boot_restart_server` 뒤). `cubrid`/`cub_admin <유틸> … <db>` 가 있으면 그 유틸리티가 이 DB 에서
도는 중이다. 디스크는 볼륨 0 의 블록 장치를 `/proc/diskstats` 에서 1초 간격으로 표본해 busy%
(`io_ticks` 증가분 / 경과)·처리량을 얻고, `/proc/<server pid>/io` 를 읽을 수 있으면 서버 몫도 얻는다.
무엇을 하는지(멈춤·감속)와 못 보는 것은 [usage.md](usage.md#옆에서-도는-것의-감지-proc-만-읽는다).

### 부하 내성 I/O (읽기 최소화·순차화)

서버가 디스크를 점유 중일 때 흩어진 소량 pread는 시크 단위로 밀린다. 우선순위를 올려
(ionice 상향) 서버와 경쟁하는 대신 **읽기 자체를 줄이고 순차화**한다:

- 인스펙션의 FTAB 판별은 (볼륨, 페이지)당 1회만 프로브해 캐시 —
  자동 갱신 틱마다 반복되던 pread가 캐시 적중 시 0회
  (실측: 틱당 2,417회 → 129회, 약 -95%). 수동 `r`은 캐시를 버리고 재프로브.
- 창 진입·패널 섹터 미리보기 시 `posix_fadvise(WILLNEED)` 1회로 해당 연속 범위를
  순차 선행읽기 — 부하 중 수천 번의 시크를 수 MB 순차 I/O로 대체.
- 패널 섹터 미리보기는 64회 분산 프로브 대신 **섹터 1MB를 단일 pread**로 읽어
  페이지 헤더와 `--deep` 집계를 한 번에 얻는다 (커서 이동당 syscall 64→1).
- `-m` 상주(mincore) 계산은 **화면에 떠 있는 볼륨만** — 토글·자동 틱은 현재 볼륨,
  볼륨 전환·기동 시에는 그 볼륨이 처음 나타날 때 지연 계산 (배치 모드는 전 볼륨 유지).

### 증분 라이브 갱신

`r`(수동)/`a`(2초 자동): 섹터테이블 재독 + 기존 파일의 변경 확인 + 트래커 변경 확인 + 무소유
신규 섹터만 프로브. 상시 켜 둘지는 이 양을 보고 판단한다.

- 파일마다 헤더 페이지의 32바이트 앞부분만 읽어 **페이지 LSA** 를 지난 순회 때와 비교한다. 할당·해제·섹터
  변경은 모두 헤더 카운터를 고치므로 LSA 가 그대로면 섹터 테이블도 그대로다 — 그 파일은 지난 순회가 남긴
  섹터 목록을 다시 적용하고 페이지를 읽지 않는다. LSA 가 움직인 파일만 헤더와 파일 테이블을 다시 읽는다.
  임시 볼륨의 페이지는 엔진이 LSA 를 상수(`PGBUF_TEMP_LSA`)로 두어 움직이지 않으므로, 그 볼륨의 파일(temp·query area)은
  캐시하지 않고 매번 다시 읽는다 — 스필이 커지거나 같은 헤더 페이지에 새 임시 파일이 생겨도 놓치지 않기 위해서다.
- 트래커도 페이지마다 32바이트만 읽어 LSA 를 비교하고, 하나도 안 움직였으면 항목 순회를 건너뛴다(체인에
  페이지가 붙으면 앞 페이지의 `vpid_next` 가 바뀌어 LSA 가 움직인다).
- 실측(웜, 틱당 읽기량; 시간은 이 장비 기준 참고치): 파일 792개 2.7GB DB 에서 0.11MB(3.5ms), 파일 76개 97GB DB 에서
  0.18MB(5ms). 헤더를 매번 다시 읽던 때는 각각 13MB, 2.2MB 였다. 파일 수에 비례하는 항은 파일당 32B 와 해시 조회 하나뿐이다.
- 검증은 `tools/check-refresh.sh`: 변화 없는 DB 에서 refresh 3회가 전부 캐시 적용·트래커 생략으로 같은 보고를
  내고, 테이블을 만들어 채운 뒤의 refresh 가 새로 돌린 결과와 같다.

### 터미널 처리 주의점 (재발 방지 지식)

- ESC 시퀀스는 CSI 최종바이트(0x40–0x7E) 규칙으로 종료 판정 — 키 버스트에서 입력을 삼키지 않는다.
- autowrap OFF(`ESC[?7l`) 필수 — 하단 행이 폭을 넘겨 래핑되면 화면 전체가 스크롤되어 프레임이 겹친다.
- 역상(SGR 7) + 전체 블록(█)은 자기상쇄로 투명해진다 — 커서 표현에 사용 금지.

## 5. 3스레드 구조 (인터랙티브 전용)

배치·JSON 경로는 스레드를 만들지 않는다. `-i` 만 3스레드로 돈다 — 스레드 기동 실패 시
단일 스레드 경로로 자동 폴백.

```
UI 스레드                        워커 A (배치 레인)               워커 B (저지연 레인)
 키입력/렌더/터미널/시그널  ──▶  ① 점진 스캔 슬라이스             ③ 콜드 섹터 1MB 읽기의
 self-pipe 웨이크업 수신   ◀──  ② refresh: 섀도 재구축→포인터 스왑    페이지캐시 워밍(큐 깊이 1)
 (스캔 진행/완료/워밍 완료)      ③ -m residency 재읽기
```

- **섀도 커밋**: 볼륨 메타 4종(stab/owner/alloc/pagebm)에 쓰기측 포인터(`w_*`)를 두고
  디스커버리 코드는 전부 `w_*` 경유로 읽고 쓴다. 평시에는 읽기측의 별칭이라 단일 스레드
  경로는 무변화. refresh 때만 `w_*` 가 섀도 배열을 가리키고, 재구축 완료 후 읽기측 포인터를
  스왑한다(구 배열은 다음 섀도로 재사용, UI 프레임 카운터로 재사용 시점 가드) —
  **UI 가 반쯤 재구축된 지도를 보는 일이 없다.**
- **공개는 프레임 경계에서만**: 스왑은 UI 가 배열을 읽지 않는 순간(`ui_reading == 0`, `select()` 대기 중)에만
  한다. UI 가 그 순간에 오지 않으면(도움말 화면은 열려 있는 동안 계속 프레임 중이다) 스왑을 포기하고
  틱마다 다시 시도한다.

  | 재시도 시점의 상황 | 동작 |
  |---|---|
  | 그대로 | 섀도에 남은 스캔을 **다시 스캔하지 않고** 재공개 — 파일 테이블 재독 0 |
  | 새 새로고침 요청(`r`·틱)이 들어옴 | 버리고 새로 스캔 — 요청이 재공개에 소비되지 않는다 |
  | `r` 이 볼륨 목록을 바꿈(목록 세대 `list_gen` 변경) | 버리고 새로 스캔 — 새 볼륨에는 스캔 결과가 없다 |
  | 섀도 할당 실패 | 재요청하지 않는다(재시도로 풀리지 않음) |

  섀도를 이번에 새로 만든 볼륨이 있으면 재공개 요청이어도 스캔하고, 새 `owner` 섀도는 -1(소유자 없음)로
  시작한다 — 위 규칙이 놓치는 경로가 생겨도 초기화되지 않은 값이 공개되지 않는다.
- **워밍 레인**: 워커 B 는 섹터 1MB 를 자기 버퍼로 pread 해 페이지캐시만 덥히고 버린다.
  UI 는 기존 동기 채움을 캐시 히트로 수행 — 채움/렌더 로직 재구성 0줄. 요청 후 15ms 만
  대기(웜 데이터 깜빡임 방지), 콜드면 이전 패널을 유지하고 완료 웨이크업에서 재도장.
- **self-pipe**: 워커→UI 신호(스캔 진행 150ms 스로틀·refresh 완료·워밍 완료)는 파이프
  한 바이트로 UI 의 select() 를 깨운다.
- **fd 고정**: 배치 모드의 2슬롯 MRU fd 캐시는 스레드 간 close/번호 재사용 레이스이므로,
  인터랙티브는 전 볼륨 fd 를 선개방·고정한다.
- **볼륨 목록 변경 동기화**: `[r]` 재스캔은 사라진 temp 볼륨의 fd 를 닫고 배열을 당긴다.
  두 워커 모두 볼륨 포인터·fd 를 쥔 채 읽으므로, 재스캔은 `a_busy`(배치)와 `b_busy`(워밍)
  **둘 다** 해제될 때까지 기다린 뒤에만 목록을 바꾼다. 한쪽만 기다리면 다른 쪽이 닫힌
  (또는 번호가 재사용된) fd 로 읽거나 이동된 배열 항목을 참조한다.
- 스캔 중 owner[]/파일 카운터는 무락 판독(x86-64 정렬 저장·단조 증가) — 최악이 "한 프레임
  늦게 색이 붙는" 표시 지연이다.

**실측 (90GB·9볼륨, DONTNEED 강제 콜드)**: 콜드 refresh 중 키→프레임 ≤0.1s(refresh 자체는
백그라운드), 콜드 초기 스캔 중 입력 유실 0, 콜드 섹터 오버레이 열기도 수십 ms(이 장비 기준),
유휴 CPU 0.0%.

### 5.1 볼륨 목록 변경과 레인 경합

temp 볼륨(`<db>_t<NNNNN>`)은 수명이 짧아 `[r]` 마다 디렉터리를 재스캔한다. 그런데
워커 A 는 `ctx->nvols` 와 볼륨 배열을 락 없이 훑으므로, 그 도중에 배열을 줄이면
**해제된 메모리를 읽는다**.

그래서 워커 A 가 볼륨 배열을 만지는 구간을 `a_busy` 로 표시하고, 재스캔은
UI 스레드에서 **레인이 idle 해질 때까지 기다린 뒤** 수행한다. 사라진 볼륨은 fd 와
배열 4종(+섀도 4종·residency·bufmap)을 해제한 뒤 배열을 당겨 구멍을 메운다.

`a_busy` 는 refresh·residency 재읽기뿐 아니라 **파일 탐색 단계 전부**를 덮는다. 특히
2차 패스(소유자 미상 섹터의 전 페이지 — 256개 이하면 자동, `--full-sweep` 이면 전부)는 `scan_active` 가 내려간 뒤(= `r` 이 더 이상 거부되지 않는 때) 돌고
큰 DB 에서 수 분이 걸리므로, `a_busy` 없이는 재스캔이 그 순회와 겹친다. 대기 상한을 넘으면
그 회차의 재스캔은 건너뛴다. 재스캔 중에는 장벽(`list_frozen`)이 서 있고, 워커는 새 일을 시작하지 않고
대기한다. 목록이 실제로 바뀌면 장벽을 내리기 전에 목록 세대(`list_gen`)를 올려, 보류된 공개가 옛 목록
위의 스캔을 재사용하지 못하게 한다.

### 5.2 격자 상태

섹터·페이지 격자는 규약이 같다 — 창 크기(`w × rows`)가 정해지고, 창이 전체의 일부만
덮으면 `base` 부터 보여 주며 뒤에 더 있으면 `+` 를 단다. 이 네 값을 격자마다
`VOLMAP_GRID` 로 갖고, 스크롤 계산은 **공용 `volmap_grid_clamp()` 하나**를 쓴다.

드릴다운 박스 폭(`VOLMAP_OV_W`)은 읽기 전용 매크로이고 쓰기는 `volmap_ov_w_set()`
한 곳뿐이다 — 프레임 시작에서 한 번 정하고 그 프레임 안에서는 상수처럼 쓴다.
같은 프레임의 여러 격자가 서로 다른 폭으로 계산하는 일을 막는다.

## 6. 두 가지 실행 형태

**유지관리 대상은 ② 단독 바이너리다.** ①은 트리 통합 시의 참고 형태로 남긴다.

**① 정식 유틸리티** — `cubrid volmap`. 기존 `cub_admin` dlopen 관례를 따르며
(`volmap.c`가 cubridcs/cubridsa 양쪽에 컴파일).
등록 방법은 [integration/cubrid-tree.md](../integration/cubrid-tree.md).

**② 단독 바이너리** — `cub_volmap`. 정적 링크(1.3MB, `glibc-static` 이 있을 때)로
어느 리눅스 x86_64에나 파일 하나 복사로 동작한다. CUBRID 미설치 장비·구버전(10.x) 서버·
백업 볼륨 분석용. `volmap_standalone.cpp`가 프레임워크 심볼(옵션 접근자 4종,
databases.txt 파서 3종)을 자체 구현해 CUBRID 라이브러리에 전혀 링크하지 않는다.
