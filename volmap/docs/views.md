# 화면 해설 (Views)

cub_volmap 의 모든 화면과, 각 표시가 어떤 데이터에서 오는지의 해설이다.
키·옵션 레퍼런스는 [usage.md](usage.md), 데이터 수집 구조는 [architecture.md](architecture.md) 참조.

## 1. 배치 지도 (기본 실행)

```
⠿⠿ catalog(sys)  ⠿⠿ data  ⠿⠿ index  ⠿⠾⠶⠴⠤=alloc 100..20%  ⠂ resv-empty  ⠂ unreserved  # meta
cbench [  1/11] volid 0  12.0GB  sectors 12287/12288 reserved (x64 = 786368 pages)  (cell = 344 pages = 5.4MB)
pages 786368 reserved / 781873 allocated  (idle 4495 pages = 70.2MB)  owner switches 707
#⠿⠿⠿⠿⠿⠾⠿⠿⠿⠿⠿⠿⠿⠶⠿⠿⠿⠿⠿⠿⠿⠿⠿⠿⠿⠿⠿⠿▖▖▖⠿⠿⠿⠿⠿⠿⠿⠿⠿…
BY KIND
  DATA      files    35  reserved      35MB  allocated     3.0MB  idle   32.0MB ( 91.6%)
  ...
```

- 볼륨당 [범례 / 헤더 2줄 / 지도 / BY KIND 집계] 블록이 반복된다. 임시 볼륨(`<db>_t<N>`)도 자동 포함.
- 1칸 = ⌈총페이지/칸수⌉ 페이지를 **섹터(64페이지=1MB) 배수로 스냅** — 헤더의 `(cell = …)`이 항상 딱 떨어진다.
- `idle` = reserved − allocated (예약만 하고 안 쓴 공간), `owner switches` = 톤 반전 횟수 = 조각화 지표.
- `--check` 를 붙이면 말미에 FINDINGS 절(무결성 소견, 소견 존재 시 종료코드 2), `--format json` 은 전체를 JSON 으로.

## 2. 인터랙티브 프레임 (-i)

```
행 1        범례 (고정)
행 2        [n/N] 볼륨 헤더  (스캔 중 "scanning NN%")
행 3        (공백)
행 4..H-4   ╭┤ DB명 ├────────┤ pages·idle·owner switches ├╮   ← 라운드 프레임 + inset 3종
            │  지도 (셀 커서 = 역상)                        │
            ╰───────────┤ perm|perm temp|temp temp vol N: 경로 ├──╯
행 H-3..H-2 인스펙션 2줄 — 커서 대상의 FULL 상세 (live)
행 H-1      키 목록: [sp/rtn]drill-down [1-3]box [bksp]up [<>]volfile [r]efresh [a]uto …
```

- **인스펙션 2줄**이 정보의 중심이다: `⠿⠿ vol 0 › sect 12754..12755 › page … ›  H dba.hits
  #file-table page VFID 0|4736 | file: 5404800 pages (…) | cell 5/173` — 크럼(위치) › 종류 배지 +
  객체명 › 페이지/슬롯 통계 › 파일 통계 순. 커서 이동·클릭마다 갱신된다.
- **종류 배지**: ` H `(힙, 파랑 칩) / ` I `(인덱스, 초록 칩) — ASCII 한 글자 색 칩 접두 — 배경색 = 지도 종류색.
  `[g]`는 이제 테두리에만 관여한다(배지는 ASCII 칩이라 모드 무관).
- 마우스 단일 클릭 = 커서 이동 + 인스펙션. **더블클릭 = space/enter와 동일한 한 단계 드릴다운** (지도에서는 오버레이 열기, 박스 안에서는 다음 뎁스).
- 첫 실행 시 상태줄이 `new here? h = guide | l = 한글` 로 시작해 도움말·한글 전환의 입구를 알린다.
- 진입 시 기존 쉘 내용은 지우지 않고 **스크롤백으로 밀어올린 뒤**, 터미널 기본 배경을 어두운 색(#101010)으로 바꾸고(OSC 11) 종료·시그널 시 원복한다(OSC 111) —
  밝은 바탕 클라이언트에서도 지도 색이 그대로 보인다. OSC 미지원 터미널은 무해하게 무시.

## 3. 드릴다운 오버레이 (space/enter, tab)

지도 위에 겹치는 세로 4박스 스택(폭 36, 내용 32칸)이다. 지도를 대체하지 않고 떠 있으며,
오버레이 사각형 밖의 지도는 계속 클릭·이동 가능하다. 커서가 오버레이 위치와 겹치면
반대쪽으로 자리를 옮긴다.

```
  H dba.hits (184 sectors)            ← 앵커 섹터의 소유 파일 캡션 (지도 남색 마킹과 짝)
╭┤ sector 12754  (del 3 vac 1) ├──╮   ← --deep 시 섹터 집계 병기
│ ⠿⠿⠿⠾⠶⠿⠿ … (32×2 = 64페이지)  │   [1] 섹터 그리드 — 페이지 선택(파랑), 경계에서 이웃 섹터로 크로스오버
╰─────────────────────────────────╯
╭┤ page 816257 (2/64) ├───────────╮   ← -m 이면 "res n/4" (OS 캐시 상주) 병기
│ ⠉⠿⠿⠿⠿⠤⠤⠛ … (페이지 전 바이트) │   [2] 바이트 분포 — 셀=다수결 클래스, 커서는 데이터 셀에만
│ ⠉ hdr  ⠿ rec  ⠤ free  ⠛ dir     │      rec 색 = 소유 파일 종류색 (데이터=파랑, 인덱스=초록)
│ ⠶ frag - del  0 vac  0   48B/cell│      free/dir/frag 는 중립 회색 — 종류색과 충돌하지 않음
╰─────────────────────────────────╯
╭┤ slots 21 ├─────────────────────╮
│ HHHHHNRH-… (스크롤 창)           │   [3] 슬롯 — 선택 슬롯 역상, H home N new R reloc B big D/d del
│ H home N new R rel B big D/d del │
╰─────────────────────────────────╯
╭┤ info ├─────────────────────────╮
│ OID 0|816257|3                   │   뎁스별 선택의 간결한 정체 (F1 객체부 / F2 클래스+~bytes /
│  H dba.hits                      │    F3 OID+배지·객체명)
╰─────────────────────────────────╯
```

- **한 키 사다리**: space 또는 enter 를 누를 때마다 지도→[1]→[2]→[3]→지도 로 한 단계씩.
  `1`/`2`/`3` 은 박스 직행, bksp 는 한 단계 위로. 최심부([3])에서는 화살표=슬롯 선택뿐이고
  space/enter/bksp 모두 지도 복귀.
- 위 박스의 선택이 아래 박스들을 실시간 갱신한다 (섹터에서 페이지를 고르면 [2][3]이 그 페이지로).
- 하단 인스펙션 2줄은 오버레이 중에도 **전 뎁스 FULL 상세**를 계속 보여준다 — info 박스는 요약,
  하단은 전체라는 분담.
- 색 계약이 전 뎁스에 흐른다: 지도 셀 색 = [1] 그리드 색 = [2] rec 색 = 배지 배경색.
- **동일 파일 멀티 섹터 표시**: 드릴다운이 앵커한 섹터의 소유 파일이 가진 다른 모든 지도 셀에
  남색 마킹이 자동으로 켜진다(물리 지도는 그대로, dim 없음) — 파일이 볼륨에 얼마나 흩어져
  있는지가 드릴다운의 부산물로 보인다. 앵커를 옮기면 따라오고, 닫으면 꺼진다.
- 커서(선택 하이라이트)는 **데이터가 있는 셀에만** 머문다 — 범례 행·user 영역 밖 꼬리 셀로는
  이동하지 않는다.
- 빈(미할당) 페이지는 더 들어갈 내용이 없어 space 가 안내만 하고 멈춘다.
- 반복 압축: 같은 모양이 연속되면 `패턴행 / x217 / 패턴행` 으로 접는다(섹터 그리드는 `Npg`).

## 3.5 파일 뷰 (f)

볼륨 안 파일 목록(물리 첫 섹터 순, 이름·소유 섹터 수)이 우측 박스로 뜨고, 선택한 파일의 **객체(클래스) 전체**가 마킹된다 — 힙 남색·인덱스 진초록·오버플로 어두운 주황
배경, 객체 밖만 회색으로 물러난다. 목록은 객체 단위로 묶인다(힙 아래 그 인덱스들·오버플로,
오버플로 행은 주황 글리프 + " ovf"). 열 때 지도 커서
아래의 파일이 자동 선택되며, 커서를 움직이면 목록 선택이 따라온다 — "이 테이블이 볼륨 어디에
얼마나 흩어져 있나"를 한 번에 본다(volume → file → sector). space/enter 는 그 파일의
첫 섹터로 커서를 점프시키고, 하단바가 파일 상세(배지·VFID·유형·섹터/페이지 통계)를 보여준다.

## 4. 캐시 상주 뷰 (-m / m 토글)

배경색 오버레이 — 전경(색·글리프)은 그대로 두고 배경만 칠한다.

| 배경 | 의미 |
|---|---|
| 밝은 회색(240) | 셀의 ≥80% 가 OS 페이지캐시 상주 |
| 어두운 회색(237) | ≥30% |
| 없음 | 콜드 |
| 하늘색(24) | 하이워터마크 셀(볼륨 마지막 할당 페이지) — 회색(캐시)이 우선, 해제되면 하늘색 복귀 |

지도·오버레이 섹터 그리드에 모두 적용되고, 페이지 박스 제목에는 `res n/4`(16KB 페이지의
4KB 서브페이지 상주 수)로 표기된다. 수집은 mmap+mincore — 커널 메타데이터만 읽어
폴트·락·실읽기 0. 계산은 화면에 떠 있는 볼륨만 한다.

## 4.5 버퍼풀 뷰 (-B FILE / b 토글)

cub_top 이 `--bcb-dump FILE` 로 남긴 cub_server 버퍼풀(BCB 배열) 스냅샷을 지도에 얹는다.
 -m 이 "OS 페이지캐시"라면
이 층은 "엔진 버퍼풀"이다. 두 층을 함께 켜면 디스크 → 페이지캐시 → 버퍼풀이 한 셀에서 읽힌다.

| 배경 | 의미 | 우선순위 |
|---|---|---|
| 자주(53) | 셀 안에 **볼륨에 아직 반영되지 않은** 버퍼 페이지가 있다 — BCB 의 DIRTY 비트 또는 FLUSHING 비트(쓰기 시작, 완료 전)가 선 페이지. 엔진은 flush 를 시작할 때 DIRTY 를 내리고 FLUSHING 을 세우며 쓰기가 끝나야 FLUSHING 을 내리므로, 두 비트가 모두 꺼진 페이지만 볼륨과 같다고 볼 수 있다 | 파일 마킹(남색/초록/갈색)·체인(빨강) 아래, 나머지 위 |
| 청록(23) | 셀 안에 버퍼풀 상주 페이지가 있다(전부 clean) | 자주 아래 |
| 회색(240/237) | -m 페이지캐시 상주 | 청록 아래 |
| 하늘(24) | 하이워터마크 | 맨 아래 |

표기 위치:

| 위치 | 표기 | 의미 |
|---|---|---|
| 볼륨 헤더(2행) | `buf 2080 pages (unflushed 59, flushing 3, freed 26)` | 이 볼륨의 버퍼 상주 페이지 수 / 미반영(dirty 또는 flushing) / 그중 flushing / 미할당인데 버퍼에 남은 페이지(해제 후 victim 대기 — 정상). flushing·freed 는 0 이면 생략 |
| 하단 인스펙션 | `[buf 4/64 UNFLUSHED 1]` (브레드크럼 바로 뒤) | 이 셀 64페이지 중 4장이 버퍼에, 그중 1장이 미반영 |
| 페이지 박스 제목 | `page 642 (3/64) buf:DIRTY unflushed` | 메모리 페이지 LSA > 디스크 페이지 LSA — 아직 볼륨에 반영 안 됨. 비트 상태는 `DIRTY` / `FLUSHING` / `DIRTY+FLUSHING` / `clean` 으로 구분 |
| | `buf:FLUSHING flushed`, `buf:DIRTY flushed` | 스냅샷엔 미반영이었지만 지금 디스크 LSA 가 같다 — 그 사이 쓰기가 끝남(연속성이 실시간으로 닫히는 모습) |
| | `buf:clean unflushed (in DWB?)` | 두 비트가 모두 꺼졌는데 디스크가 뒤처져 있다 — 이중 쓰기 버퍼(DWB)에서 볼륨 쓰기를 기다리는 페이지. 비트로는 안 보이고 LSA 비교로만 드러난다 |
| | `buf:clean` / `buf:-` | 버퍼에 있음(동일 내용) / 버퍼에 없음 |
| | `buf:clean disk-newer!` | 디스크가 더 새롭다 — 정상 경로에서는 나오지 않음(스냅샷 오염 의심) |
| 상태바(`b`) | `buffer pool @03:46:20: 14540/32768 pages resident, 59 unflushed \| log append 564167\|16152 flushed 564167\|16152 \| oldest dirty LSA 564033\|0` | 스냅샷 요약: 시각·상주·미반영(cub_top 이 DIRTY 또는 FLUSHING 으로 센 수)·로그 꼬리/반영 경계·최고령 dirty LSA |

갱신: 자동 새로고침 틱과 `r` 에서 파일 mtime 이 바뀌었으면 다시 읽는다(cub_top 라이브가 매 프레임 덧쓴다).
페이지 박스의 디스크 LSA 는 그 페이지 헤더 8B 를 pread 한다(캐시 영향 1페이지).

실측(demodb, `update game set medal=medal` 직후): 스냅샷 dirty 55장 중 24초 뒤 디스크와 대조해 55장 전부 메모리 LSA > 디스크 LSA(unflushed); 체크포인트 뒤 같은 페이지는 `DIRTY flushed` 로 읽힘. 볼륨별 buf 수는 cub_top `pgbuf.vol<N>.resident` 와 9/9 볼륨 일치.

## 5. 도움말 (h) / 한·영 (l)

- `h`: **한 문서 스크롤**이다(페이지 넘김이 아니다). 3부로 이어진다 —
  ① 계층·지도·키·용어 ② 드릴다운 4박스 읽는 법 ③ slot·record·row 의 관계.
  `↑↓` 한 줄, `space`/`PgDn`·`b`/`PgUp` 한 화면, `g`/`G` 처음·끝, `q` 닫기.
  하단 안내바가 `1-24/69 ▼ 더 있음` 처럼 위치와 잔량을 표시한다.
- **파일 뷰(`f`)가 열린 상태에서 `h`** 를 누르면 파일 뷰 전용 도움말이 뜬다(목록 읽는 법·남색 마킹·`space` 점프). 지도·드릴다운 설명은 그 화면에서 쓸모가 적어 분리했다.
- `l`: 인터랙티브 UI 한/영 전환 (배치 출력은 영문 고정 — 골든·파서 호환).
  한글 IME 를 끄지 않고 눌러도 두벌식 키 위치 역매핑으로 동작한다 (`ㅂ`=q, `ㄱ`=r, …).

### 5.1 슬롯이 없는 페이지

슬롯 디렉터리는 `heap`·`btree`·`overflow` 페이지만 가진다. 그 외는 자기 고유 포맷이라
슬롯이 없으며, **왜 없는지**를 페이지 종류로 알린다.

```
slots n/a - qresult page    정렬·조인 결과 버퍼
slots n/a - area page       범용 작업공간
slots n/a - ftab page       파일의 페이지 목록표
```

temp 볼륨은 대부분 `AREA`·`QRESULT` 다(실측 예: AREA 5,557 / QRESULT 256 / UNKNOWN 182).
이들은 OID 로 참조되지 않고 실행기가 순차로만 읽으므로, 슬롯이라는 간접층이 **없는 것이 정상**이다.
`UNKNOWN` 이 대부분인 볼륨은 할당만 하고 아직 쓰지 않은 상태를 뜻한다.

## 6. 상태 표기의 신뢰도

| 표기 | 성격 |
|---|---|
| 색·램프·톤, 슬롯/OID/오프셋 | **측정** — 온디스크 바이트에서 직접 |
| `?` 소유자 미상 | 예약됐는데 어느 파일도 주장하지 않는 섹터 — 할당 여부를 알 수 없으므로 `_`(빈 공간)로 그리지 않는다. 대부분 스냅샷 시차(삭제 뒤 vacuum 전)이고, r 후에도 남으면 무결성 의심(--check 의 `unknown_owner_sectors`) |
| `⠒` (스캔 중 자리표시) | 아직 안 읽음 — 스캔 완료 시 실제 소유 색으로 바뀜 |
| 바이트 셀의 `~bytes` 오프셋 | **근사** — 분포가 클래스별 정렬이라 빈 칸이 낄 수 있음 (표기에 ~ 명시) |
| slots 제목 `(unallocated)` | 미할당 페이지 — 내용 자체가 없음 (깨진 것 아님) |
| slots 제목 `corrupt?` / `?` 슬롯 | **할당된 페이지의 범위 밖 헤더·무효 레코드 유형 — 손상 의심을 있는 그대로 노출** (이 뷰어는 손상 추적 용도를 겸하므로 절대 감추지 않는다) |
| 헤더 상세줄 `db_created ?(N)` | page 0 의 생성 시각이 날짜로 바꿀 수 없는 값(찢긴 헤더 등) — 날짜 대신 **디스크의 원래 값 N 을 그대로 노출** |
